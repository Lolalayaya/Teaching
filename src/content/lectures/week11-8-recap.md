## 一、拆解與抽象化

**第1關**：玩家多猜一次，這件事要再做嗎？

| 開始做一次 | 每次猜都要做 | 結束做一次 |
| --- | --- | --- |
| 隨機想一個答案 | 問玩家猜多少 | 說「答對了！猜了○次」 |
| 「次數」歸零 | 記下玩家猜的數字 | |
| 「猜測」先設成0 | 比大小，說太大或太小 | |
| | 「次數」加1 | |

**第2關**：只要三個變數：**答案、猜測、次數**。只留下需要的資料，叫做**抽象化**。

## 二、設計演算法

**第3關**：下週照這個寫。

```
當綠旗被點擊
將「答案」設為（隨機取數 1 到 100）
將「次數」設為 0
將「猜測」設為 0
重複直到 ＜「猜測」＝「答案」＞
　詢問「猜一個1～100的數字」並等待
　將「猜測」設為「回答」
　將「次數」改變 1
　如果「猜測」＞「答案」那麼　說「太大了」
　如果「猜測」＜「答案」那麼　說「太小了」
說「答對了！你猜了（次數）次」
```

- 先**詢問**，才有「回答」
- 先存進**「猜測」**，才能比大小

**第4關**：

| 題目 | 答案 |
| --- | --- |
| 猜中就停 | 「猜測」＝「答案」 |
| 寫成「猜測」＞「答案」 | 猜得比答案大就結束，沒猜中也一樣 |
| 最多猜7次 | （「猜測」＝「答案」）**或**（「次數」＝7） |

## 三、追蹤與除錯

**第5關**：答案40。

| 玩家猜 | 電腦說 | 次數 |
| --- | --- | --- |
| 50 | 太大了 | 1 |
| 25 | 太小了 | 2 |
| 37 | 太小了 | 3 |
| 43 | 太大了 | 4 |
| 40 | 不說，迴圈停止 | 5 |

這5個數字，每次都是範圍的正中間。

**第6關**：

| 程式 | 錯在哪 | 現象 |
| --- | --- | --- |
| 甲 | 用「如果…否則」 | 猜中時還先說「太小了」 |
| 乙 | 「次數改變1」放在迴圈外 | 最後永遠說「猜了1次」 |
| 丙 | 少了「將猜測設為回答」 | 一直說「太小了」，停不下來 |
| 丁 | 直接用「回答」比對 | 偶爾一開始就說「猜了0次」 |

## 四、效率分析與找規律

**第7關**：1～100最多猜幾次？依序猜 **100**、猜中間 **7**、亂猜**說不準**。

**第8關**：

| 範圍 | 最多猜幾次 |
| --- | --- |
| 1～10 | 4 |
| 1～100 | 7 |
| 1～1000 | 10 |
| 1～1,000,000 | 20 |

每次砍一半，所以範圍變大很多，次數只多一點。「猜中間」就是**第九週的二分搜尋**；1～100本來就排好了，所以不用先排序。
