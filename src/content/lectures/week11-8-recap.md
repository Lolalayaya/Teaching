## 學習目標

- 複習猜數字遊戲的結構：迴圈前、迴圈內、迴圈後各要做什麼
- 複習迴圈步驟的順序與停止條件
- 複習四種常見錯誤和它們造成的現象
- 複習二分搜尋最多要猜幾次的規律

## 一、第一階段：拆解與抽象化

### 第1關：拆解遊戲

| 開始時做一次（迴圈前） | 每猜一次都要做（迴圈內） | 結束時做一次（迴圈後） |
| --- | --- | --- |
| 隨機想一個1～100的數字當作答案 | 問玩家：「猜一個1～100的數字」 | 說「答對了！你猜了○次」 |
| 把「次數」歸零 | 把玩家輸入的數字記下來 | |
| 把「猜測」先設成0 | 比較猜的數字和答案，說太大或太小 | |
| | 「次數」加1 | |

這三格就是程式的骨架：**迴圈前**準備、**迴圈內**重複、**迴圈後**收尾。判斷的方法是問自己：「玩家多猜一次，這件事要不要再做一次？」

### 第2關：電腦要記住什麼

一定要的變數只有三個：**答案、猜測、次數**。玩家的名字、背景顏色和遊戲能不能玩沒有關係；「玩家猜過的每一個數字」也用不到，因為電腦每次只要拿「這一次」猜的數字比大小就好。

把不必要的資料拿掉、只留下解決問題需要的，叫做**抽象化**。

## 二、第二階段：設計演算法

### 第3關：排出迴圈裡的步驟

```
當綠旗被點擊
將「答案」設為（隨機取數 1 到 100）
將「次數」設為 0
將「猜測」設為 0
重複直到 ＜「猜測」＝「答案」＞
　詢問「猜一個1～100的數字」並等待
　將「猜測」設為「回答」
　將「次數」改變 1
　如果「猜測」＞「答案」那麼　說「太大了」
　如果「猜測」＜「答案」那麼　說「太小了」
說「答對了！你猜了（次數）次」
```

順序有兩個一定要遵守的地方：

1. **先詢問，才有回答**：「回答」是玩家回答問題之後才有的。
2. **先把回答存進「猜測」，才能比大小**：兩個「如果」用的是「猜測」。

「次數改變1」跟其他步驟沒有先後關係，放在迴圈裡的哪個位置都可以。兩個「如果」誰先誰後也都可以。

### 第4關：迴圈什麼時候停

| 題目 | 答案 | 說明 |
| --- | --- | --- |
| 猜中就停 | 「猜測」＝「答案」 | 條件寫的是**停下來的時機** |
| 條件寫成「猜測」＞「答案」 | 猜得比答案大就結束，就算沒猜中 | 條件寫錯，迴圈會在錯的時候停 |
| 最多只能猜7次 | （「猜測」＝「答案」）**或**（「次數」＝7） | 兩種情況只要一種發生就停，用「或」；用「且」的話要兩個同時成立才停 |

這跟第十週搜尋的停止條件是一樣的想法：「找到了」**或**「確定找不到」。

## 三、第三階段：追蹤與除錯

### 第5關：追蹤變數

答案是40：

| 第幾次 | 玩家猜 | 電腦說 | 「次數」 |
| --- | --- | --- | --- |
| 1 | 50 | 太大了 | 1 |
| 2 | 25 | 太小了 | 2 |
| 3 | 37 | 太小了 | 3 |
| 4 | 43 | 太大了 | 4 |
| 5 | 40 | 不說提示，迴圈停下來 | 5 |

第5次猜中時，兩個「如果」都不成立，所以電腦什麼提示都不說；接著回到「重複直到」檢查條件，「猜測」＝「答案」成立，迴圈停下來，說「答對了！你猜了5次」。

仔細看玩家猜的數字：50、25、37、43、40，每一次都是**還有可能的範圍的正中間**。這位玩家用的就是第四階段的「猜中間」。

### 第6關：從怪現象找出錯誤

| 程式 | 錯在哪裡 | 會出現的現象 |
| --- | --- | --- |
| 甲 | 用「如果…否則」，猜中時也會走進「否則」 | 猜中的那一次，還會先說「太小了」才結束 |
| 乙 | 「次數改變1」放在迴圈**外面**，整局只會加一次 | 不管猜幾次，最後都說「你猜了1次」 |
| 丙 | 少了「將猜測設為回答」，「猜測」一直是0 | 不管猜什麼都說「太小了」，猜中了也停不下來 |
| 丁 | 直接拿「回答」比對，「回答」會留著上一局最後輸入的數字 | 如果新的答案剛好跟上一局一樣，偶爾一開始就說「答對了！你猜了0次」 |

除錯的方法：先看到**現象**，再想「哪一步沒有做、做錯位置、或做錯時機」才會造成這個現象，最後回到程式裡找那一步。

## 四、第四階段：效率分析與找規律

### 第7關：三種猜法比一比

| 猜法 | 範圍1～100最多猜幾次 | 說明 |
| --- | --- | --- |
| 依序猜 | 100次 | 答案是100的時候最慘，就是第九週的循序搜尋 |
| 亂猜 | 說不準 | 運氣好1次就中，運氣很差可能跟依序猜差不多 |
| 猜中間 | 7次 | 每次排除一半，不管答案是多少，最多7次一定猜到 |

比較演算法的時候，常常看的是**最壞的情況**：猜中間保證7次內一定猜到，所以最穩定。

### 第8關：找出規律

| 範圍 | 最多要猜幾次 |
| --- | --- |
| 1～10 | 4 |
| 1～100 | 7 |
| 1～1000 | 10 |
| 1～1,000,000 | 20 |

範圍變成10倍，次數只多3～4次；範圍到一百萬，也只要20次。原因是每猜一次，範圍就少掉一半。

「每次猜中間」就是**第九週的二分搜尋**。二分搜尋的前提是資料已經排好順序，猜數字不用另外排序，因為1～100本來就是由小到大排好的。
