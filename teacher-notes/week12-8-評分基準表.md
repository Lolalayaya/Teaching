# 第十二週（8年級）解碼行動 評分基準表

**繳交跟評分走Scratchy**（沿用W4、W6、W8、W10的模式）：學生填班級座號姓名＋上傳`.sb3`＋執行結果截圖，系統用scratch-vm模擬執行、對照參考解答（`teacher-notes/week12-8-guess-solution.sb3`）算出建議分數，老師在Scratchy的老師後台審核後才正式公布。政策跟之前一致：**數字／名稱必須跟指定的完全一樣才算分**。

參考解答由`teacher-notes/scripts/generate-week12-8-guess-sb3.py`產生，已用（2026-11-18改過的）Scratchy評分引擎實際跑過：自己比自己動態分數10／10；提示只用「說」、沒改成「說…2秒」的版本也是10／10（最後狀態一樣，不會被扣分）；答案寫死成40的版本只有8.8／10（答案、最後那句話對不上）。

**系統測試的答案是60，刻意跟講義讓學生自己測的40不同**（老師2026-11-23決定）：學生測完忘了把答案改回隨機、或直接寫死40，就會被比對出來。講義只說「另一個數字（不是40）」，沒寫出60，避免學生改寫死成60。

## 這份作業為什麼需要Scratchy的新功能

這是第一份用到「詢問」和「隨機取數」的Scratchy作業。原本的Scratchy兩個都過不了：沒人回答「詢問」，模擬會卡住；隨機數每次不同，參考解答跟學生的結果沒辦法比。2026-11-18在Scratchy加了**「模擬玩家輸入」**（作業設定頁「範例解答」區塊下方），範例解答和學生作品會拿到完全一樣的輸入：

- 「詢問」依序回答：每執行一次「詢問」就交出下一個回答，回答用完那段程式就停下來
- 「隨機取數」固定為：每個「隨機取數」都回傳這個數字（不在積木範圍內就照常隨機）
- 有設定模擬輸入的作業，「說／想＿持續＿秒」會立刻結束（原本Scratchy等不完真實的秒數，整段會卡住）

**有學生繳交之後，模擬輸入就不能再改**（跟規則一樣，改了會讓已經算好的分數對不上）。

## 必要檢查規則（5條，共5分，每條1分）

Scratchy的必要規則是5分平均分給每一條，規則類型都選「積木使用」，opcode直接打：

| opcode | 最少幾個 | 對應積木 | 為什麼要這條 |
| --- | --- | --- | --- |
| `sensing_askandwait` | 1 | 詢問＿並等待 | 遊戲核心 |
| `operator_random` | 1 | 隨機取數 | 寫死40動態比對已經會扣分；但學生剛好寫死成60，動態比對會完全一樣，只有這條抓得到 |
| `control_repeat_until` | 1 | 重複直到 | 猜中才停 |
| `control_if` | 2 | 如果…那麼 | 抓「如果…否則」的錯（講義第七節第一列）：最後狀態一樣，動態比對抓不到 |
| `looks_sayforsecs` | 2 | 說出＿持續＿秒 | 抓「提示被詢問蓋掉」沒修好（講義第五節）：最後狀態一樣，動態比對抓不到 |

不設加分規則：Scratchy的加分會讓總分超過100，而且講義挑戰題寫「不計分」。之後想鼓勵挑戰題，可以加`VARIABLE_EXISTS`「最小」（挑戰1）或`BLOCK_USAGE` `operator_or`（挑戰2），講義的「不計分」也要一起改。

## Scratchy 的模擬順序

只有綠旗一個事件：**綠旗 → 結束**。答案固定60，模擬玩家照「猜中間」依序輸入50（太小）、75（太大）、62（太大）、56（太小）、59（太小）、60，第6次猜中，迴圈結束。

## 配分（總分100分）

Scratchy自動算：基本分85＋動態行為10＋必要規則5。

動態行為10分的比對項目：舞台7項（背景、位置等固定值，幾乎一定對）＋3個變數，角色7項（含說的話）。各項平均分配，所以：

| 常見情況 | 大約結果 |
| --- | --- |
| 全對 | 10分 |
| 答案寫死成40（測完沒改回隨機） | 少2項（答案≠60；6個回答用完沒猜中，最後那句沒說出來） |
| 「次數改變1」放在迴圈外（次數＝1，說「猜了1次」） | 少2項 |
| 最後那句字不一樣（半形!、少「次」） | 少1項 |
| 最後那句用「說…秒」（模擬結束時對話框已清空） | 少1項 |
| 小貓被拖離中間（超過5像素） | 少1～2項 |
| 變數建成「僅適用當前角色」 | 少3項（變數在角色身上，舞台上找不到） |
| 小貓改名或刪掉 | 少7項 |

## 審核時要注意

- **變數建成「僅適用當前角色」、小貓改名**：程式其實是對的，只是位置／名稱對不起來。看截圖確認遊戲能玩，可以手動改分
- **少了「將猜測設為回答」（一直說太小了）**：6個回答用完那段程式就停了，次數會是6、猜測是0，動態分數會少，屬於真的錯誤
- **用「如果…否則」**：最後狀態跟正確答案一樣，自動批改抓不到（猜中時會多說一次「太小了」，但最後會被「答對了」蓋掉）。講義第七節有教，這一項不特別扣分
- **做了挑戰題**：最小／最大變數、最多猜7次，都不影響比對（參考解答沒有這些變數，不會比；6次就猜中，不會碰到7次上限）
- 截圖只是快速確認，有疑問就打開`.sb3`自己玩一次
