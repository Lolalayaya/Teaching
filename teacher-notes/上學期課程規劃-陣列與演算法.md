# 上學期課程規劃：陣列與演算法（八年級）

內部教學用，不發布到網站上。八年級學生去年（七年級）已經學過 Scratch 基礎程式設計，這學期銜接資料結構（陣列／清單）與演算法思維，用「不插電活動 → Scratch實作」交替的節奏進行。

**這份文件的狀態**：第1~20題已透過 grilling 逐題問過老師確認，第6堂起不再是草案，是已定案的內容。之前「第三週課程討論」沒有留下紀錄的部分，都已經在這次的問答裡重新釐清。

## 為什麼這樣安排

不插電活動先讓學生用身體、實體卡片理解抽象概念，接著回頭用 Scratch 把同一個概念重新實作一次——兩種理解方式互相補強，也呼應七年級「導論→資料處理應用專題→Scratch」的重排邏輯（見 [[project_teaching_site_semester1_7th_grade]]）：內容順序服務於教學效果，不必照課本順序。

## 重要限制

- **不使用課本習作**：全部練習/評量改用網站自製的互動頁面（見 `feedback_no_workbook` 記憶）
- **資訊課一週1節**（每班）
- **段考不考筆試，採平時作業成績平均**：每一堂/活動結束都有一個小測驗或作業（比照第1~3堂已經在用的Google表單模式），段考當天的成績＝從上次段考以來所有作業分數的平均。段考檢查點不需要特別設計「大成果」，只要維持每堂都有小測驗/作業的節奏，段考當天現有的東西平均起來就是成績。
- 各班上課日不同、假期撞期影響不同，**原則是「教到哪就以當下內容評分」**，不用勉強讓各班進度對齊
- 三次段考實際日期：**10/13、10/14**／**11/26、11/27**／**1/19、1/20**

### 期末專題：猜數字進階版

- **核心玩法**：程式在範圍內想一個數字，玩家用二分搜尋邏輯（太大/太小提示）猜
- **整合設計**：遊戲可玩多輪，每輪猜測次數記錄進一個清單；結束後把清單排序、顯示「最佳成績」與「歷史紀錄」——同一個作品同時秀到清單、排序、搜尋三塊這學期教過的內容，不是刻意塞進去的功能
- **繳交方式**：完成後上傳到學生自己的scratch.mit.edu帳號。清單能不能真的跨堂持續累積不強求——這牽涉到Scratch的清單/變數只有「存檔當下」的數值會被保留、且很多初學者寫法會在綠旗腳本清空清單，能存最好、存不下去也沒關係，不特別花時間教「記得存檔、不要清空清單」這類操作細節
- **預估堂數**：3~4堂（規劃/搭骨架 → 核心猜數字邏輯 → 清單記錄+排序找最佳成績 → 潤飾/上傳/發表），實際依現場進度彈性調整
